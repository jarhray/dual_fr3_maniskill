# 线槽与 Rope-Actor 分段性能对照（2026-09-16）


## 当前默认：日常快速模式

根据用户“日常只需看起来接近，需要时再切换高精度”的要求，默认简化配置
采用固定步长。以下设置仅作用于 `cable_solver:=rope_actor`；启动后端默认值仍为 MPM。

| 参数 | 日常 `trunking_cable_simplified_2mm.yaml` | 精细 `trunking_cable_simplified_2mm_precise.yaml` |
| --- | ---: | ---: |
| `rope_actor.links` | 151 | 101 |
| `rope_actor.frequency` | 1000 Hz | 1000 Hz 基础频率 |
| `rope_actor.adaptive_timestep` | false，固定 1 ms | true，按运动继续细分 |
| 位置/速度求解迭代次数 | 200 / 10 | 40 / 10 |
| `cable.friction` | 0.1，低阻力预览近似 | 0.5 |
| `cable.penetration_tolerance` | 0.8 mm | 0.1 mm |
| `rope_actor.constraint_tolerance` | 2 mm | 1 mm |
| `rope_actor.max_stretch_ratio` | 1% | 未设置 |
| `rope_actor.max_contact_travel` | 固定模式不使用 | 0.05 mm |

默认缺失 `adaptive_timestep` 时仍为 true，旧配置行为保持兼容。频率必须为
桥接 `sim_freq` 的整数倍。固定模式不计算自适应距离/速度预算，也不会沿用上一周期的小步长；
场景每个子步仍处理真实接触、代理反作用力、夹持观测与力采集。
每控制周期仍检查穿透、关节连接、穿孔和非有限状态。验收阈值不修改碰撞形状或驱动力。

精细配置保留首次性能交付时的独立副本（101 段、7 mm 根部）。日常配置保留用户后续
选择的 151 段、5 mm 根部和 0.8 mm 穿透验收阈值。当前两份配置并非单参数精度对照。
第 09 阶段供线与累计拉长的修复见 [rope_feed_fix.md](rope_feed_fix.md)。

在原启动命令中添加以下参数即可选择精细配置：

```bash
cable_config:="$PWD/src/dual_fr3_maniskill/config/trunking_cable_simplified_2mm_precise.yaml"
```

不指定配置，或继续指定原来的 `trunking_cable_simplified_2mm.yaml`，就是日常快速模式。
切换需要重启仿真。两套配置都已安装到包的 share/config 目录。

## 短测结果

同一机器、准备关节姿态、双手打开、USB 与局部线缆临时支撑、静止目标，
无 GUI / ROS / 力采集器。每项独立进程顺序运行；生成后预热 5 个控制周期，
测量 10 个周期，共 0.2 秒仿真时间。控制 50 Hz，Rope-Actor 基础 1000 Hz，
PGS 40/10 次迭代，接触运动上限 0.05 mm，其他材料参数一致。

| 网格 | 总段数 | 普通段长 / mm | 0.2 秒仿真耗时 / s | 实时率 |
| --- | ---: | ---: | ---: | ---: |
| 上一简化版 | 151 | 9.953 | 3.941 | 0.0507 |
| 新版 | 151 | 9.953 | 3.327 | 0.0601 |
| 新版 | 101 | 14.930 | 1.930 | 0.1036 |
| 新版 | 76 | 19.907 | 1.985 | 0.1008 |

根部始终为 7 mm；总中心线长度 1.5 m、线径 2 mm、线缆质量 22.5 g 不变。
这里的段长指胶囊两端半球中心之间的长度；几何总长还包含两端半径。

仅换网格本次耗时降低约 15.6%；再改为 101 段，比新网格 151 段降低约 42.0%。
101 段相对原来整套配置约快 2.04 倍，但仍约需 9.65 秒墙钟时间推进 1 秒仿真。
这些是一次短时样本，76 和 101 的小差异不足以确定性能排序，不能外推为整段走线速度。
各次运动状态和自适应子步数并不相同；这衡量的是配置整体效果，并非单次碰撞算子的速度。

四组均通过创建与每控制周期的内置物理检查。101 段短测最大关节间隙约
0.0090 mm、最大测得穿透约 0.0074 mm；76 段分别约 0.0128 和 0.0071 mm。
短测不能代替夹持释放、窄槽转弯和完整 MTC 路径验证。

## 为什么更长不一定更快或保持相同行为

- `rope_actor.links` 决定刚体和 D6 关节数量。代码按新段长计算质量、惯量、关节端点和穿孔直线余量，不依赖固定 151 段索引。
- 更长的刚段降低弯曲分辨率，转弯时可能跨过原来的弧线、顶到槽壁或夹指；初始曲线若超出关节弯曲上限会明确报错。
- 每关节阻尼、角度限位及 `inertia_floor` 不随分段数自动标定。改段数会改变整体弯曲响应，即使总质量和长度相同，也不是完全相同的材料模型。
- 端点转动速度含 `段长/2 × 角速度`。贴近碰撞物时，自适应步长仍受 0.05 mm 运动上限约束；段数减少并不保证子步同比减少。
- 现有 `convex_capsule` 用于处理已复现的孔沿/槽沿接触问题，不能把改回普通胶囊、放宽穿透阈值与加长分段混作一次优化。

PhysX 的关节收敛还依赖质量/惯量比及迭代次数，参见
[NVIDIA 关节文档](https://nvidia-omniverse.github.io/PhysX/physx/5.4.0/docs/Joints.html)。
这里实际使用 SAPIEN 2 内的 PhysX；新版文档只用于说明通用求解原则。
